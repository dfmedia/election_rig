# Team assumptions

Written before fieldwork (Nov 10, 2026) so findings can be scored against them afterward. Source: project brief.

Scoring after synthesis: **Supported**, **Mixed**, **Contradicted** or **No evidence**, with the participant IDs and quotes behind it.

| # | Assumption | Why it matters | Score | Evidence |
|---|---|---|---|---|
| 1 | Newsrooms want to set up their own races and charts; some may prefer central setup. | The adoption goal rests on it. | | |
| 2 | Setup effort, not reliability, is the biggest pain. (Election-night errors were a database limit that's now fixed.) | Decides where build effort goes first. | | |
| 3 | Sites stay off the rig because setup is hard, not because their own tool (Denver, SCNG, AP embeds) does something the rig can't. Kickoff notes already point the other way for Denver. | Decides what the new tool must match. | | |
| 4 | Markets differ in configuration, not in workflow; one tool can serve everyone with settings. | Decides the data model and admin design. | | |
| 5 | Readers want more charts and maps, rather than faster, simpler, more legible results. | Decides display and maps scope. Tested in reader research. | | |
| 6 | Local races are where we win readers (the top rig page was Virginia local results). | Decides local-race priority. | | |
| 7 | Print needs stay as they are today (agate files) for MVP. | Decides print scope. | | |
| 8 | The Virginia scraper approach can scale to other states' local races. | Decides the local-data roadmap. | | |
